# Інтернаціоналізація (i18n)

Цей документ — **єдине джерело істини** для всіх вимог локалізації.

Пов'язані документи:

- **Тематизація** (Light/Dark) і **іконки** — див. [UI-UX-v6.md](UI-UX-v6.md).
- **Атрибут `<html lang>` як a11y-вимога** — див. [ACCESSIBILITY-v6.md § 9](ACCESSIBILITY-v6.md).
- **Локалізація user-facing помилок** — див. [ERROR-HANDLING-v6.md § 4.3](ERROR-HANDLING-v6.md).

## 🚫 ЖОРСТКІ ОБМЕЖЕННЯ (ANTI-PATTERNS)

| Рівень       | Заборона                                                                   | Правильна альтернатива                                                          |
| ------------ | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| **CRITICAL** | Хардкод user-facing рядків у `.svelte` / `.ts` (`'Зберегти'`, `'Помилка'`) | Імпорт з Paraglide: `m.button_save()`, `m.error_generic()`                      |
| **CRITICAL** | Використання `writable`-store для locale (Svelte 4 стиль)                  | Paraglide runtime або клас з `$state` у `.svelte.ts`                            |
| **CRITICAL** | Зміна мови без оновлення `<html lang>`                                     | Paraglide hooks/handle оновлюють атрибут автоматично                            |
| **CRITICAL** | Конкатенація рядків для побудови речень (`'Знайдено ' + n + ' елементів'`) | Параметризовані повідомлення з ICU MessageFormat: `m.found_items({ count: n })` |
| **HIGH**     | Один словник `messages.json` на всі мови у public-бандлі                   | Окремий файл/модуль на мову + lazy load для додаткових                          |
| **HIGH**     | Відсутність CI-перевірки повноти перекладів                                | `inlang` / власний скрипт перевіряє наявність усіх ключів у всіх locales        |
| **HIGH**     | Форматування дат / чисел / валют через `toLocaleString` без `locale`       | Передавати поточний `locale` явно або використовувати Paraglide-обгортку        |

## 1. Стек

### Контрольний список

- [ ] Базова бібліотека: **Paraglide.js** (`@inlang/paraglide-sveltekit`) — рекомендація команди SvelteKit. Type-safe, tree-shakeable, zero-runtime.
- [ ] Альтернативи (для legacy-проєктів): `svelte-i18n`, `typesafe-i18n`, `tolgee`. Усі **обов'язково** мають TypeScript-типізацію ключів.
- [ ] Власна реалізація на `$state` — допускається **тільки** для дуже малих проєктів (≤ 50 рядків), і обов'язково має типізований `Dictionary` interface.

---

## 2. Налаштування Paraglide

### Контрольний список

- [ ] Ініціалізація:

```bash
npx @inlang/paraglide-js init
npm i @inlang/paraglide-sveltekit
```

- [ ] `project.inlang/settings.json` визначає мови та `baseLocale`:

```json
{
	"$schema": "https://inlang.com/schema/project-settings",
	"baseLocale": "uk",
	"locales": ["uk", "en", "pl"],
	"modules": ["https://cdn.jsdelivr.net/npm/@inlang/plugin-message-format/dist/index.js"]
}
```

- [ ] `vite.config.ts` підключає Paraglide-плагін:

```typescript
import { paraglide } from '@inlang/paraglide-sveltekit/vite';

export default defineConfig({
	plugins: [paraglide({ project: './project.inlang', outdir: './src/lib/paraglide' }), sveltekit()]
});
```

- [ ] У `hooks.server.ts` встановлено `paraglideHandle`, що оновлює `<html lang>` та locale на сервері.

## 3. Конвенції ключів

### Контрольний список

- [ ] **Формат:** `<feature>_<element>_<state>` у snake_case (Paraglide вимагає валідні JS-ідентифікатори):
  - `home_title`
  - `auth_button_login`
  - `error_network_timeout`
  - `cart_items_count`
- [ ] **Без UI-prefixes** типу `btn_*`, `lbl_*` — описуй контекст, а не елемент.
- [ ] **Заборонено** ключі типу `text1`, `msg2` — лише семантичні.
- [ ] **Параметри** іменуються змістовно: `m.welcome({ name })`, не `m.welcome({ x })`.
- [ ] Ключі **не скорочуються**: `auth_button_login`, не `ath_btn_lgn`.

---

## 4. Атрибут `<html lang>`

### Контрольний список

- [ ] При SSR — `<html lang>` встановлюється у `app.html` через placeholder, який Paraglide замінює:

```html
<html lang="%paraglide.lang%"></html>
```

або через `+layout.server.ts`:

```typescript
export const load = async ({ locals }) => ({
	locale: locals.paraglide?.lang ?? 'uk'
});
```

- [ ] При клієнтській зміні мови — атрибут оновлюється автоматично через Paraglide reactive `lang()` runtime.

## 5. Параметри та плюралізація

### 5.1 Параметризовані повідомлення

- [ ] Повідомлення з підстановкою — через ICU MessageFormat:

```json
{
	"welcome_user": "Вітаємо, {name}!",
	"items_in_cart": "{count, plural, =0 {Кошик порожній} one {# товар} few {# товари} many {# товарів}}"
}
```

- [ ] Виклик у компоненті:

```svelte
<script>
	import * as m from '$lib/paraglide/messages';
</script>

<p>{m.welcome_user({ name: user.name })}</p><p>{m.items_in_cart({ count: cart.length })}</p>
```

### 5.2 Слов'янська плюралізація (3 форми)

- [ ] ICU `plural` категорії для української/російської: `one` (1, 21, 31...), `few` (2-4, 22-24...), `many` (0, 5-20, 25-30...).
- [ ] **НЕ** використовувати власну функцію `plural(n, one, few, many)` якщо є Paraglide ICU — він робить це коректно за CLDR.

### 5.3 Дата, час, число, валюта

- [ ] Усі форматування — через `Intl` із поточним `locale`:

```typescript
import { lang } from '$lib/paraglide/runtime';

const fmtDate = (d: Date) => new Intl.DateTimeFormat(lang(), { dateStyle: 'medium' }).format(d);
const fmtMoney = (n: number) =>
	new Intl.NumberFormat(lang(), { style: 'currency', currency: 'UAH' }).format(n);
```

- [ ] Заборонено `toLocaleString()` без явного locale — він використовує системний, а не вибраний користувачем.

## 6. RTL (Right-to-Left)

### Контрольний список (для проєктів із арабською/івритом)

- [ ] `<html dir="rtl">` встановлюється для RTL-локалей.
- [ ] CSS використовує **logical properties** замість `left/right`:
  - `margin-inline-start` замість `margin-left`
  - `padding-inline-end` замість `padding-right`
  - `inset-inline-start` замість `left`
- [ ] Іконки зі стрілками (`←`, `→`) дзеркаляться через `:dir(rtl)` селектор або `transform: scaleX(-1)`.

---

## 7. Зміна мови

### Контрольний список

- [ ] Перемикач мов реалізований як **посилання** (`<a hreflang="...">`), не кнопка з `goto()` — це працює без JS і коректно для SEO.
- [ ] URL-стратегія: `/{locale}/path` (рекомендовано Paraglide) або subdomain (`uk.example.com`). Заборонено: тільки cookie без URL — Google не індексує переклади.
- [ ] При відсутності перекладу для поточної locale — **fallback** на `baseLocale` із попередженням у dev-консолі.
- [ ] При зміні мови **користувацький стан** (форми, фільтри) зберігається — оновлюється лише UI-текст.

---

## 8. SEO

### Контрольний список

- [ ] `<link rel="alternate" hreflang="uk" href="https://example.com/uk/page">` для кожної локалізованої версії сторінки.
- [ ] `<link rel="alternate" hreflang="x-default" href="...">` для дефолтної версії.
- [ ] `og:locale`, `og:locale:alternate` мета-теги для соцмереж.
- [ ] Sitemap містить URL для всіх локалей.

## 9. Тестування i18n

### 9.1 Перевірка повноти ключів (CI)

- [ ] Скрипт `scripts/check-translations.ts` (або вбудована команда `inlang validate`) запускається у CI:

```typescript
// scripts/check-translations.ts
import { readFileSync, readdirSync } from 'fs';

const locales = ['uk', 'en', 'pl'];
const messages = locales.map((l) => ({
	locale: l,
	keys: Object.keys(JSON.parse(readFileSync(`./messages/${l}.json`, 'utf-8')))
}));

const baseKeys = new Set(messages[0].keys);
let hasErrors = false;

for (const { locale, keys } of messages.slice(1)) {
	const missing = [...baseKeys].filter((k) => !keys.includes(k));
	const extra = keys.filter((k) => !baseKeys.has(k));
	if (missing.length || extra.length) {
		console.error(`[${locale}] missing: ${missing.length}, extra: ${extra.length}`);
		if (missing.length) console.error('  missing keys:', missing);
		hasErrors = true;
	}
}

if (hasErrors) process.exit(1);
```

- [ ] CI-крок:

```yaml
- run: npm run check:i18n
```

- [ ] PR блокується, якщо в одній з локалей бракує ключів.

### 9.2 Pseudo-locale у dev-режимі (опціонально)

- [ ] Додатковий «pseudo» locale (`xx-pseudo`), що замінює всі рядки на `[!! Ţëšţ ţëẍţ !!]` — допомагає швидко знаходити:
  - Хардкод-рядки (вони НЕ зміняться)
  - Обрізаний layout (псевдо-текст на 30% довший)
- [ ] Активується через query-param `?locale=xx-pseudo` лише у dev.

### 9.3 Unit-тести плюралізації

- [ ] Для критичних повідомлень із плюралом — Vitest-тест на крайні випадки:

```typescript
import * as m from '$lib/paraglide/messages';

describe('items_in_cart', () => {
	it.each([
		[0, 'Кошик порожній'],
		[1, '1 товар'],
		[3, '3 товари'],
		[5, '5 товарів'],
		[21, '21 товар'],
		[25, '25 товарів']
	])('%i → %s', (count, expected) => {
		expect(m.items_in_cart({ count }, { locale: 'uk' })).toBe(expected);
	});
});
```

### 9.4 E2E з різними локалями

- [ ] Хоча б один Playwright-test проходить критичний сценарій у **кожній** locale:

```typescript
for (const locale of ['uk', 'en', 'pl']) {
	test(`checkout works in ${locale}`, async ({ page }) => {
		await page.goto(`/${locale}/checkout`);
		// ...
	});
}
```

- [ ] Sitemap містить всі локалі
