# Контекст проєкту: SeatWise

## 1. Загальні відомості

- **Назва**: SeatWise (Система оптимізації розсадки учасників нетворкінгу)
- **Опис**: Інтелектуальний веб-додаток для оптимізації розсадки учасників на бізнес-івентах та нетворкінг-сесіях (задача Social Golfer Problem). Гарантує максимальну кількість унікальних знайомств та мінімізує колізії (повторні зустрічі) між учасниками впродовж кількох раундів.
- **Стек**: SvelteKit 2 (`@sveltejs/kit`), Svelte 5 (виключно Runes), TypeScript (Strict Mode), `@sveltejs/adapter-static`, Paraglide.js i18n, Lucide Svelte, CSS Variables.
- **Хостинг**: GitHub Pages (`https://alik532ua.github.io/SeatWise/`).
- **Гілка деплою**: `main`.

## 3. Реєстр префіксів сховища (STORAGE-NAMESPACE-v10 § 1)

Сайт використовує суворо ізольований префікс для всіх записів у `localStorage` та `sessionStorage`. Прямий доступ повз фасад `$lib/services/storage.ts` заборонено (перевіряється тестом `src/security.test.ts`).

- **Префікс сховища**: `seatwise_`
- **Фасад доступу**: `src/lib/services/storage.ts`

### Реєстр ключів сховища:

| Ключ                   | Призначення                                                | Область          |
| :--------------------- | :--------------------------------------------------------- | :--------------- |
| `seatwise_theme`       | Збереження активної теми (`light` \| `dark`)               | `localStorage`   |
| `seatwise_skin`        | Активний UI-скін (`professional` \| `compact` \| `visual`) | `localStorage`   |
| `seatwise_last_config` | Останні введені параметри івенту (учасники, столи, раунди) | `localStorage`   |
| `seatwise_history`     | Збережена історія розсадки для поточного заходу            | `sessionStorage` |

## 4. Математичний апарат та архітектура алгоритмів

Розв'язання задачі розсадки розділено на два рівні з математичним доведенням оптимальності:

1. **Афінна площина порядку 8 над кінцевим полем Галуа $GF(8)$**:
   - Застосовується для еталонної конфігурації: 64 учасники, 8 столів по 8 місць ($N=64, T=8, C=8$).
   - Математично гарантує рівно 9 раундів ($8+1$), у кожному з яких будь-які два учасники зустрічаються рівно один раз (0 колізій).
   - Розрахунок базується на рівняннях прямих на площині $y = m \cdot x + c$ з арифметикою поліномів за незвідним многочленом $x^3 + x + 1 = 0$.

2. **Евристичний стохастичний жадібний алгоритм з пошуком мінімуму колізій**:
   - Застосовується для довільних конфігурацій $(N, T, C)$, де точні проективні або афінні площини не існують або конфігурація не є квадратом простого числа.
   - Оптимізує матрицю суміжності пар за жадібним критерієм з локальним перебором перестановок.

## 5. Архітектура компонентів та Skin-система

Додаток реалізує повне відокремлення інтерфейсного представлення від реактивного стану:

- **Контролери стану (`$lib/controllers/`)**:
  - `SeatingController.svelte.ts`: Зберігає матрицю учасників, поточний раунд, історію розсадок, статистику повторів та керує навігацією між раундами через Runes (`$state`, `$derived`).
  - `UIController.svelte.ts`: Керує активним скіном інтерфейсу.
  - `ThemeController.svelte.ts`: Керує синхронізацією колірної теми.

- **Скіни інтерфейсу (`$lib/components/skins/`)**:
  - `ProfessionalSkin.svelte`: Табличний огляд для ведучих івенту з друкованою версією карток столів.
  - `CompactSkin.svelte`: Щільне представлення для мобільних пристроїв.
  - `VisualSkin.svelte`: Інтерактивна 2D-візуалізація круглих столів та місць учасників.

## 6. Безпека та CSP (SECURITY-v10 & CSP-v10)

- **Контентна політика безпеки (CSP)**:
  - Суворо налаштована в `svelte.config.js`.
  - Динамічний розрахунок SHA-256 хешів для інлайн-скрипта теми в `app.html` під час білду.
  - Заборона `unsafe-inline` для скриптів, блокування сторонніх підключень (`connect-src: 'self'`).
- **Захист від XSS**:
  - Заборона сирого `{@html}` без попередньої санітизації.
  - Регулярне тестування у `src/security.test.ts` та `src/csp-hash.test.ts`.

## 7. Надійність та Error Boundaries (ERROR-HANDLING-v10 § 2.2)

- Глобальне перехоплення помилок через `<svelte:boundary>` у кореневому макеті `+layout.svelte`.
- Захист від застарілих чанків після деплою (Stale-Build Protection): автоматична перевірка версії клієнта.
- Безпечний фасад сховища: перехоплення квот та блокувань пам'яті в приватному режимі браузера.

## 11. Свідомі відхилення від канону

1. **Повністю клієнтський розрахунок без сервера**:
   - _Причина_: Івенти часто проводяться в умовах нестабільного зв'язку або офлайн. Повний алгоритм розсадки займає < 50мс у браузері, тому серверні API-роути не потрібні.
2. **Paraglide.js замість самописного i18n**:
   - _Причина_: Забезпечує строго типізовані ключі перекладів під час компіляції без оверхеду в рантаймі.
